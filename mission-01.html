Mission 01 — The Blockchain Locker

Lesson 1: Syntax, Data Types & State Variables

  • read and write the basic structure of a Solidity file
  • choose the right data type for a piece of data
  • declare, read and change state variables
  • explain the difference between what a contract remembers permanently (storage) and data that disappears after a call
THEORY

1.1 THEORY — What is Solidity?

Simply: Solidity is the language you use to write programs — called smart contracts — that run on Ethereum and compatible blockchains.

Technically: Solidity compiles to EVM bytecode. That bytecode is stored on-chain and executed by every node in the network whenever a transaction calls it. There is no single server — thousands of computers run the same code and must agree on the result.

You write Solidity source → the compiler produces bytecode → it's deployed to the blockchain → every node executes it.

Prediction question: Solidity is primarily used to write — A. Mobile apps B. Smart contracts C. Operating systems D. Databases

Reveal

B. Solidity targets the EVM, not phones, kernels or databases.

ANALOGY

1.2 ANALOGY — The vending machine in a public square

A smart contract is like a vending machine bolted into a public square. Anyone can walk up, follow its rules, and get a result. Nobody can quietly rewrite the rules inside once it's installed, and everyone can see every sale it has ever made.

A contract's state variables are the machine's internal counters: how many drinks are left, how much money is inside. They persist between customers.

EXAMPLE

1.3 EXAMPLE — Anatomy of a Contract

We build this up piece by piece.

Step 1 — the shell

contract Locker {
}

A contract is similar to a class in object-oriented languages: a template with its own data and behavior.

Step 2 — the compiler version

pragma solidity ^0.8.24;

"Compile this with version 0.8.24 or a newer 0.8.x version." The ^ allows newer patch versions — which is why GradLearn also tells you to pick exactly 0.8.24 in Remix.

Step 3 — add state

contract Locker {
  uint256 number;
}

Full file:

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract Locker {
  uint256 number;
}
  • // SPDX-License-Identifier: MIT — a machine-readable license tag. The compiler warns if it's missing. Etherscan also asks for it during verification.
  • pragma solidity ^0.8.24; — the compiler version rule.
  • contract Locker { ... } — defines a contract named Locker.
  • uint256 number; — a state variable: declared at contract level, stored permanently in contract storage.

Syntax rules to remember:

  • Every statement ends with ;
  • Blocks use { }
  • // starts a single-line comment, /* ... */ a multi-line comment
  • Names are case-sensitive: Owner and owner are different
THEORY + EXAMPLE

1.4 THEORY + EXAMPLE — Data Types, Defaults & Integer Boundaries

uint256 age;
bool active;
address owner;
string name;
TypeHoldsDefault value
uint256whole numbers from 0 to 2^256 − 10
booltrue or falsefalse
addressa 20-byte account or contract identifieraddress(0) (0x000…000)
stringUTF-8 text"" (empty)

Key facts:

  • Every variable starts at its default value. There is no "undefined" or "null" in Solidity.
  • uint means unsigned — it cannot be negative. There are smaller sizes (uint8 holds 0–255), but uint256 is the standard choice for counts and balances.
  • Since Solidity 0.8.0, arithmetic is checked: if a result would go above the maximum or below zero, the transaction reverts instead of silently wrapping around.
  • string is more expensive to store than value types like uint256 and bool.

INTERACTIVE — Overflow prediction

uint8 public small = 255;

function bump() public {
  small = small + 1;
}

Predict: what happens when you call bump()?

Reveal

The transaction reverts with an arithmetic overflow error, and small stays 255. In old Solidity (before 0.8) it would have wrapped silently to 0 — a source of real exploits. Checked arithmetic is one reason the course pins a modern compiler.

In this lesson you only need to know:

  • State variables (declared at contract level) → storage, permanent.
  • Function parameters and local variables → temporary, gone when the call ends.

uint256 public total; // storage

function add(uint256 amount) public { // amount is temporary
  uint256 doubled = amount * 2; // doubled is temporary
  total = total + doubled;
}

PRACTICE

1.6 PRACTICE — Build a Student Profile

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract StudentProfile {
  string public name;
  uint256 public age;
  bool public enrolled;
}

Do this in Remix:

  1. Create a new file StudentProfile.sol and type the contract (typing beats pasting while you learn).
  2. Open the Solidity Compiler tab, select 0.8.24, click Compile.
  3. Open Deploy & Run Transactions, set Environment to Remix VM (a local simulated blockchain — no wallet, no real network). Click Deploy.
  4. Expand the deployed contract and click each getter: name, age, enrolled. Note the default values.
  5. Notice there's no way to change anything. Keep that observation — you'll fix it next.
Why public? Marking a state variable public makes the compiler generate a getter function for it. You didn't write name() — the compiler did.

Important: public controls whether a getter is generated. It does not control secrecy. Everything stored on a public blockchain can be read by anyone, including private variables (see 1.10).

EXAMPLE

1.7 EXAMPLE — Changing State with a Function (preview)

Functions get a full lesson in Mission 02. For now, just the shape:

uint256 public score = 10;

function increaseScore() public {
  score = score + 5;
}

Code prediction: What is score after calling increaseScore() twice? A. 10 B. 15 C. 20 D. 25

Reveal

C — 20. 10 → 15 → 20. Each call reads the current stored value and adds 5. Run it in Remix and confirm.

EXAMPLE

1.8 EXAMPLE — Giving the Locker an Owner (constructor preview)

A constructor runs exactly once — at deployment — and is where you set initial values. msg.sender is the address that sent the current transaction (explained fully in Mission 02). During deployment, that's the deployer.

address public owner;

constructor() {
  owner = msg.sender;
}

Without this, owner would stay at its default value, address(0), and nobody would ever be the owner.

DEBUG

1.9 DEBUG — The Broken Counter

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

contract Counter {
  uint256 public count

  function increase() public {
    count = count + 1;
  }
}

Task: Paste it into Remix, compile, read the error message, and fix it yourself.

Hint

The error points near the function line, but the problem is on the line just above it. What does every statement need at its end?

Reveal fix

Missing semicolon: uint256 public count; Compiler errors often point at the line after the real mistake, because that's where the compiler realized something was wrong. Always check the line above too.

CHECK

1.10 CHECK — Knowledge Check

Code reading challenge

contract Vault {
  uint256 public balance = 100;

  function add(uint256 amount) public {
    balance += amount;
  }
}
  1. What is stored permanently?
  2. What is amount?
  3. What happens when add(50) is called?
  4. What is balance afterwards?
Reveal

1. balance, in storage. 2. A temporary parameter, gone after the call. 3. balance is read, 50 is added, the result is written back to storage. 4. 150. Security flag: nothing checks who called add. Anyone can inflate balance. Mission 02 exists to fix this. Flag it, don't fix it yet.

Answer in your head or notebook, then reveal.

  1. Which type represents a wallet address?
  2. Where does a variable declared at contract level live?
  3. What does public do to a state variable?
  4. True or false: a private variable's value is hidden from everyone except the contract.
  5. What is the default value of an unset bool?
Reveal

1. address 2. In permanent contract storage. 3. It makes the compiler generate a getter function. 4. False. Anyone can read raw contract storage from outside the chain. private only stops other contracts (including inheriting ones) from accessing the variable in Solidity code. 5. false
